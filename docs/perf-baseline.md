# Performance baseline (2026-10-26)

Release build, GCC C++23, 2 vCPU Intel Xeon Platinum 8255C at 2.50 GHz,
1.9 GiB RAM and 6 GiB swap, Linux 6.8.0. Each input was converted five times
with `tests/perf/run_perf.py`; wall time is the median and RSS is the largest
peak reported by `/usr/bin/time`.

The 1/5/20 MiB DOCs are generated by LibreOffice from repeatable FODT with
chapters, tables, footnotes, headers and footers. LibreOffice's 50 MiB pure
text DOC export contains a CHPX FKP with `crun=0`, which
[[MS-DOC] §2.9.33](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/f5f10f04-d4cc-4ebd-86df-0de6d227675c)
forbids. The 50 MiB fixture repacks the valid 20 MiB structured DOC with a
30 MiB deterministic, unreferenced `Data` stream; it measures the CFB and I/O
envelope. The 100 MiB fixture instead contains five referenced copies of the
20 MiB structured body in `WordDocument` and the piece table. It exercises
real text decoding and formatting at scale.

| Input | Actual MiB | Median wall s | Peak RSS MiB |
|---|---:|---:|---:|
| 1 MiB | 1.00 | 0.037 | 16.6 |
| 5 MiB | 5.00 | 0.180 | 68.3 |
| 20 MiB | 20.00 | 0.905 | 261.8 |
| 50 MiB | 50.24 | 1.111 | 322.2 |
| 100 MiB | 99.99 | 3.990 | 1287.9 |

The 100 MiB median meets the <5 s conversion goal on this machine. The
previous single-run baseline at `fc712f2` was 14.71 s and about 1.49 GiB RSS;
the current peak is about 1.26 GiB. The five fixtures do not establish a
population p99, which needs a representative document distribution.

Reproduce with:

```bash
python3 tests/perf/gen_corpus.py
python3 tests/perf/run_perf.py
DOCCRAFT_PROFILE=1 build/src/cli/doccraft convert build/perf/structured-100mb.doc -o /tmp/perf-out.docx
```
